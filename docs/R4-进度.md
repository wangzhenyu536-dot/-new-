## 本轮交付

- PACK-05：同一技能包支持多 TXT、可选 JPEG／PNG／WebP 图片及多 Excel，保留全部原文件。正文或至少一份有效非空 TXT 满足文本条件，至少一份有效 Excel 必需。选中的每份附件都须验证，不能用其他有效材料掩盖错误附件。
- PACK-08、AUTH-07、09：`/packs/:id/edit` 支持修改标题、正文、分类，添加、替换、移除附件。普通成员仅编辑自己创建的资料；管理员可编辑全部。详情页按权限展示编辑入口，直接访问及手工 callable 同样受保护。ownerId、ownerName 和创建时间保持不变。
- PACK-09：网络失败保留当前输入和选择；同一请求重试恢复成功结果，避免重复版本。刷新恢复不是 V1 要求，没有持久化草稿。编辑冲突显示明确原因，保留未保存修改；点击“重新加载最新版本”才放弃当前修改。
- FILE-02～03：图片先检查文件签名，服务端用 Sharp 0.35.5 完整解码并检查真实格式及处理预算；拒绝 SVG／伪装格式／损坏内容／过大图片。图片和 Excel 原字节不被转换覆盖。图片使用受 Firebase Storage 规则保护的 SDK 读取、哈希复验和临时 Blob URL 展示；离开组件释放 URL。
- 多 Excel 每份独立 Worker 解析及完整范围基础波形。交互缩放、原件下载、PNG、ZIP 仍在 R6。技能包整体删除在 R7；移除当前资料的附件已在本轮实现。

## 保存完整性及权限

沿用官方 SDK、`beginUpload`／`savePack`、Admin SDK、共享合同和规则，没有模拟器专用业务分支。BeginUploadInput 增加可选 packId、expectedVersion、retainedFileIds；新附件一律新 fileId 和不可覆盖的存储路径。客户端不能直接写主记录、附件清单或角色。

编辑会话在建立、保存开始和正式事务提交时检查当前成员角色、归属、ready 状态、版本及分类状态。旧版本在暂存、验证、复制期间持续可读；所有新增附件验证完毕才在同一事务中更新主记录、当前清单、fileAccess 权限映射、版本、分类计数和幂等结果。保存失败不改变旧资料，两个版本相同的并发编辑只允许一个提交，另一个返回 versionConflict。

未更改的正式附件复用服务端已验证的结果，核对存储 generation、大小、MIME 以及事务内当前清单；不反复解析 Excel。新增／替换文件仍核对真实原件、SHA-256 和 generation。移除旧附件先在事务中标记 active=false 并从访问映射删除，再清除旧对象；即使物理清理失败，旧路径也无法再通过受保护的 SDK 读取。

每个提交会话单独记录 cleanupPaths 和 cleanupSessions。清理失败仍返回“保存成功、清理待处理”，不能误报保存失败或清除另一个版本的待处理状态；管理员 callable 和本地 `npm run uploads:cleanup` 可重试。取消／过期编辑只清理该会话新增对象，不删除复用的正式原件。未提交的新附件对其他成员不可读。

Firestore／Storage 规则沿用 R3 的可信 ready＋active 映射设计，Storage 仍只需要成员档案和主记录两次 Firestore 读取，没有开放权限或额外第三次规则读取。失效的附件文档当前保留为不可读历史记录，物理对象清理可重试；完整技能包删除流程留在 R7。
