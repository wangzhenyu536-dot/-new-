## 本轮能力

对应 AUTH-08～11、DELETE-01～02、CAT-04／06、PACK-01。

- 创建者删除自己的技能包，管理员删除全部；必须勾选确认，取消或 Escape 不改变原件。
- 开始删除先标记资料不可访问，再分组清理全部原件、清单和根记录。其他成员正在查看的页面也会自动隐藏正文、图片、波形和下载按钮。删除失败如实显示未完成状态，创建者或管理员在详情／列表的 Pending operations 中继续清理，刷新或关闭浏览器后仍能恢复。
- 持久操作记录支持重复及并发请求确认；已经完成的删除不会再次扣减数量，原 ID 不允许复活。权限在每个步骤重新核对，普通成员不能恢复别人的操作。
- 管理员改分类名称，保留分类 ID 和技能包归属；同名拒绝，原名称可重新使用。空分类不需要目标，非空分类必须选择另一个有效分类。
- 删除非空分类时先锁定源／目标分类，再逐份迁移。原作者、创建时间、文件版本、清单和原件字节保持；迁移中断可由当前管理员继续，已有资料不会产生失效分类引用。原有未完成的技能包清理会先完成，计数归零后才移除分类并解除目标锁定。
- 分类计数与新建、跨分类编辑、迁移、最终删除在同一事务中更新。既有 Spark 资料使用可信工具只新增计数及名称登记，浏览器不能伪造零计数。缺少基线时拒绝相关操作并提示准备记录。
- 管理员查看成员、设置或取消管理员；确认框说明影响。不能取消最后一位管理员，并发降级仍至少保留一位，角色变更实时更新界面权限。失败保留选择，丢失确认或重复请求核对同一收据。
- 分类迁移保留原件版本，但改变资料元数据；导出同时核对元数据更新时间，避免 ZIP 使用过期分类信息。

Spark 仍只使用 Auth／Firestore，本地与云端共用官方 SDK、规则及合同。默认英文、社区术语、双语手机流程、技能包标题字号约定保持；512 KiB／3 MiB／12 件和原始无单位数值保持。
