## 保存、权限与重试合同

1. 浏览器计算各文件 SHA-256，`beginUpload` 以可信 uid 和 requestId 预留内部会话、随机文件 ID、固定路径与计划。会话暂定 1 小时；同请求、同材料幂等，不允许同一个请求键换材料。
2. 仅成员本人可向 accepting 会话的指定路径创建文件，真实大小和 MIME 必须匹配计划；禁止覆盖、元数据修改、直接删除及上传任意额外文件。暂存不可被其他成员读取。
3. `savePack` 事务冻结会话为 validating，使用 3 分钟操作租约阻止并发提交，过期租约可重试。检查账号、当前角色和分类状态。
4. 服务端按 Storage generation 读取原文件，限制读取字节并禁止自动 HTTP 解压；核对大小、MIME、SHA-256，对 TXT／Excel 运行共享校验。Excel 错误仍返回工作表、行、列和具体原因。缺文件、校验失败、复制失败都不创建公开技能包。
5. 正式路径由服务端写入，采用 generation precondition 防止覆盖；兼容模拟器的行为，已存在对象也会先核对原字节和元数据。正式对象不由服务端生成公开下载令牌，浏览器使用带身份的 `getBytes`。
6. 关键提交前再次检查身份、角色、分类和会话操作标识。在一个 Firestore 事务中创建 ready 主记录、有效附件清单、Storage 访问映射、分类计数和幂等结果。
7. 保存成功后清理暂存副本；若清理失败，保持真实的“已保存、清理待完成”状态和内部清理记录，不误报保存失败。成功结果持续保留，因此响应丢失后重试不会再上传或创建第二份资料。

Storage 文件读取同时检查受保护 member 档案、ready 包和有效文件引用。主记录中 `fileAccess` 是用于权限判断的小型映射，和详细附件清单同事务提交；R4／R7 修改引用时必须同步维护它。这样 Storage 只读取两份 Firestore 文档，符合[官方规则限制](https://firebase.google.com/docs/rules/rules-behavior)。原件的不可变写入遵守[Cloud Storage generation 条件](https://docs.cloud.google.com/storage/docs/request-preconditions)。采样数组不写入 Firestore。

`cancelUpload` 仅本人可调用，关闭会话后清理未提交资料；不能取消活跃验证租约，也不会删除已提交正式文件。`cleanupUploads` 仅管理员可调用，处理过期会话和待清理副本。没有默认周期云任务，本地维护入口 `npm run uploads:cleanup`；当前只提供工具，管理页面在后续管理员迭代完善。

## 本地预览恢复与防护

原 Auth 模拟器内存已退出，一个原非演示临时账户的密码无法恢复。已保留该账户原 UID／资料／角色，生成本地密码重置链接，用户自行设置新密码；没有替用户指定新密码，没有发送真实邮件、没有操作真实 Firebase 账户。重置链接保存在被忽略的 `outputs/R3/local-password-reset.json`，只用于这次本地恢复。演示账户密码仍为 `EvertraceDemo2026!`。

已修复为 `.runtime/emulators/preview-tmp`、`test-tmp` 两个 OS 临时目录，除项目、端口外也隔离磁盘缓存；`.gitignore` 与 `.ignore` 都已排除整个 `.runtime`。`npm run verify` 开始前对运行中的预览做完整快照至 `.runtime/preview-backup`；正常关闭导出至 `.runtime/emulator-data`；下次启动选择最新的有效导出。原始恢复副本另存 `.runtime/recovered-preview-20261004`。不是生产备份承诺，强制中断仍应依赖已完成快照。
