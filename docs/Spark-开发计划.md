# Firebase Spark 免费版开发计划

日期：2026-10-06。用户已接受 [Spark 需求对齐](Spark-需求对齐.md) 中的让步，并授权制定新计划、继续推进。旧 R0～R9 工作及原资料保留；本计划 S0～S5 是当前开发顺序。

## 固定范围

只使用 Firebase Authentication、Firestore Standard 和静态 Hosting，保持 Spark，不关联计费、不开 Blaze、不使用 Functions／Storage 或第三方平台。原 Excel、TXT、图片按字节保留；每件 512 KB、每包合计 3 MB、最多 12 件是已确认的初始验证目标。继续保持正文或 TXT 至少有其一、至少一份 Excel、既有登录／归属／管理员权限、浏览查找、编辑删除、波形与原件／PNG／ZIP 下载。

校验由浏览器完成，数据库规则执行权限、容量、结构和原子一致性，不将浏览器预检描述成后台复验。不自动压缩原图、删减脑电数据或换算单位。旧资料未经确认不迁移、不删除；不把旧架构的测试结果算作新架构已通过。

S0 先验证单包原子完整性与基础权限，不把它当作分类迁移、全部清理、真实 Auth 邮件或云端吞吐已通过。若 12 件规则设计不成立，应继续调整设计或报告具体原因，不能静默降低已确认数量或开放权限。S0 原型可使用独立命名空间；生产数据结构与界面接入在后续轮次完成。

## 每轮执行及完成门槛

1. 根据本轮可验收行为写可执行测试代码。
2. 运行测试，确认功能缺失造成的真实失败；环境错误先处理，不作为红测试证据。
3. 实现该轮最小流程，自动修复并重新运行测试。
4. 完成本轮相关及受影响回归、类型检查、静态检查和构建。S0 没有页面变更，不声称执行了新浏览器流程。
5. 保存实际日志／结果／样例，给用户可查看报告或可运行页面与简短步骤。
6. 标为“自动验证通过待用户验收”；用户验收后进入下一轮。

测试、环境准备和缺陷修复由 agent 负责，用户只验收效果。真实设备样例、云账号等 agent 无法生成的信息按实际需要获取；不把合成数据当真实设备容量证据。

## 隔离与部署边界

S0 使用 demo-evertrace-spark-s0、Firestore 28080 和独立 OS 临时目录 .runtime/spark-s0-tmp；不得清理默认 demo-evertrace 账户、Storage、历史 data 或占用 5173。验证前保留完整预览快照。默认网页和既有 Functions／Storage 配置在切换前保持，以保护当前验收资料；原代码不作为 Spark 生产依赖。

继续遵守本地／云端共用官方 SDK、规则、数据合同和集中配置，不写模拟器专用业务。云部署在代码和检查均就绪后按用户实际授权执行，不开账单或付费资源。Spark 不连接计费，额度耗尽可能限制功能；提供真实限制及恢复办法，不承诺无限空间或永久不中断。
